- 性質：分析のみ。改善案の工数感はすべて目安（推測）である。

## 分析の前提

1. **実機判定は未完了**。設計書 `design/simcity-rebuild.md` §6.1 の R1（12 項目）／R2（10 項目）／R3（5 項目）と Dynamic Type 最大表示は、開発側の検証（HeadlessCheck、View 層の機械チェック）までで、佐事の実機判定は済んでいない。実機でしか分からない項目は本書で「未判定」と書き、推測で埋めない。
2. **ビルド (22) は未配信**。一直線テンプレート入りの 1.0.0 (22) は push 済みだが、Codemagic 無料枠の枯渇で 2026-12-01 まで TestFlight に出せない。**佐事の手元の最新は (21)** である。
3. **この VM では SwiftUI をコンパイルできない**。View 層はどのフェーズでも「構文パース＋メンバー参照照合」止まりで、画面の実挙動は一度も開発側で動かしていない（各実装ログの「未検証事項」）。
4. **HeadlessCheck は今回再実行していない**（ツールチェーンが本セッションの許可ディレクトリ外）。件数は実装ログの値を引用する。

## 1. SimCity 式：マップそのものがゲーム画面

**要求**：コントロール画面のようなパネル UI ではなく、マップ（工場）がゲーム画面。直接ラインを作って育てる（2026-11-09 の作り直し指示）。

**現状**

- 常駐画面は 1 枚。`ContentView` は `MapScene` を全面に敷き、HUD とドックを重ねる構成で、`TabView` は Views 全体に 0 件【コード：ContentView.swift:43-108】。
- HUD は 1 行（資金／収入・分／時計／WPH＋市場イベントチップ最大 2＋「123」＋歯車）【コード：HUDView.swift:18-67】。ドックは 3 ボタン（建設／問題／施設）。
- マップ上の自前オーバーレイは 6 種（ToolCard／BuildDrawer／ProblemsPopover／LotCard／RailCard／StockerCard）で、同時に 1 枚だけ出る【コード：ContentView.swift:171-227】。
- シートは 11 種：施設 5（事務所・研究棟・資料室・投入口・出荷口）＋システム 3（おかえり・ようこそ・設定）＋入れ子 3（図鑑詳細・ノード切替・欠陥分析）【コード：FacilitySheets.swift:9、ContentView.swift:140-156、HUDView.swift:73】。
- マップ上で完結する操作：装置の購入配置・移動・回転・改良・売却、レール敷設、区画購入、FOUP 追跡。
- **シート内（List 形式のフォーム）でしかできない操作**：研究の開始、製品切替、ノード切替、販売（自動販売トグル・一括売却）、補助金申請、目標とミッションの確認、歩留まり内訳の確認【コード：ContentView.swift:556、FacilitySheets.swift:426・619-623、StatsView.swift:15-92・320】。
- 事務所シートは List のセクションが 8 個（ミッション／目標／国庫補助金／累計／歩留まり／現在／市場イベント／期間損益）で、旧「統計タブ」をほぼそのまま収容している【コード：StatsView.swift:10-92】。
- 建設ドロワーは画面高の 40% を占め、4 分割のセグメント（購入／倉庫／レール／撤去）を持つ【コード：BuildDrawer.swift:17・46-51】。「撤去」タブは案内文だけで操作が無い【ログ：simcity-rebuild §2.2】。
- 新規ゲームは装置 11 台＋ロットをプリシードした完成済みラインで始まる【コード：Layout.swift:670-678、Simulation.swift:507】。プレイヤーが最初に「ラインを作る」場面は無く、最初の能動操作は増設になる。
- 設計書が決めた要素のうち未実装：建設タイルのマップへのドラッグ持ち出し、区画購入時の床アニメ、未接続チップのタップでポート点滅、ようこそカードの「見て回る」カメラ動作【ログ：r1-implementation-log §6】。事務所屋上の「次の目標の旗」は MapScene に該当描画が見当たらない【コード：MapScene.swift に旗・目標進捗の描画なし。R2 ログは途中が欠落しており経緯は不明】。

**乖離：中**

骨格（1 画面・マップ常駐・モードレス操作）は要求と合致している。一方で「パネル UI」の実体は 5 つの施設シートに移っただけで、研究・製品・ノード・販売・補助金という経営判断は今もフォーム画面で行う。β4 以降の画面に対する佐事の総評は未取得【未判定】で、「コントロール画面感が消えたか」は断定できない。

**改善案**

| やること | 工数感 | 実機判定が前提か |
|---|---|---|
| (21) で「シートを開かずに何分遊べるか」を佐事に見てもらい、パネル感が残る場所を特定する | 開発 0 | 判定そのもの |
| 事務所シートを分割する：ミッション／次の目標はマップ上（ドック上のチップ）へ出し、累計統計は奥に下げる | 小〜中（1〜2 日） | 不要（要求 5 と共通） |
| 出荷口・投入口はシートではなくマップ上カード（ToolCard と同じオーバーレイ）にする。自動販売トグルと一括売却は 2 操作で足りる | 中（2〜3 日） | 前提（判定でパネル感が指摘された場合） |
| 建設ドロワーの「撤去」タブを廃止して 3 分割にする | 小（半日） | 不要 |
| 未実装 4 点（ドラッグ持ち出し等）の実装 | 中（2〜3 日） | 前提（R1 判定で不足と言われた項目だけ） |

## 2. ラインの形：一直線

**要求**：初期ラインは輪にしない。蛇行でも輪に見えるのは不可。一直線（2026-11-11 決定、S9c）。

**現状**

- 本ディレクトリの `Layout.swift` は S9c である【コード：Layout.swift:592-678】。本線は y=6 の東向き 16 セル、戻りレーンは東端→南端 y=15→西端の 32 セル、計 48 セル。
- 数値【ログ：template-straight-log §4・§10】：

| 項目 | 蛇行（旧） | 一直線 S9c |
|---|---|---|
| レールセル | 54 | 48（本線 16＋戻り 32） |
| 運転点 WIP | 59 | 53 |
| P2 定常 | 7.458 WPH | 7.667 WPH（帯 7.125〜8.154 内） |
| 長期ラン 200k step | — | 7.688 WPH、凍結なし |
| 検出率 | 0.7822 | 0.7807 |
| 初回ロット完了 | 296 tick | 336 tick（要件 720 以内） |
| 移行後定常（P3） | — | 7.312 WPH。下限を 7.679 → 7.244 へ引き下げ（2026-11-12 佐事承認済み） |
| HeadlessCheck | 887 件 | 886 件全通過 |

- トポロジーは循環のまま。搬送モデルが一方向・1 セル 1 ロットで、循環を断つと凍結するため【コード：Layout.swift:596-599】。
- **戻りレーンは本線と同じ描画**。一直線化で Views は 1 バイトも変えていない【ログ：template-straight-log §5】。つまり戻りレーンにも同じレール素材・流れドット・シェブロンが出る。戻りレーンは y=6〜15 の矩形（16×10 セル）を描き、南岸の装置群を囲む形になる【コード：Layout.swift:640-650】。
- **工程順は左→右に単調でない**。北岸は 成膜①①→露光②②→CMP⑥→検査⑤、南岸は PKG⑦→ストッカー→エッチ③③③→注入④【コード：Layout.swift:670-678】。最終工程の PKG が投入口の隣（西端）にあり、出荷口は東端にある。蛇行時代にあった「辿り順の単調性チェック」は固定配置の照合に置き換えられた【ログ：template-straight-log §6】。
- テンプレートは新規ゲーム専用。既存セーブの配置は書き換えない【ログ：同 §8】。

**乖離：小**（見え方は【未判定】）

決定どおり実装されており、性能も帯内。ただし次の 2 点は、過去 2 回の却下理由（「一周してて、どこから出てどこへ行くのか分からない」「蛇行でも輪に見える」）に再び触れる可能性がある【推測】。

1. 外周を回る戻りレーンが本線と同じ見た目で描かれるため、南半分が「四角い輪」に読める可能性。
2. ⑦ PKG が入口側にあり、「IN → ①〜⑦ → OUT を目で辿る」は構造上できない。

**改善案**

| やること | 工数感 | 実機判定が前提か |
|---|---|---|
| (22) 配信時に「**新規開始しないと一直線にならない**」ことを佐事へ伝える（既存セーブは蛇行のまま） | 0 | — |
| 設計書の文言更新：simcity-rebuild §0.1-3 と §6.1 R1-1 がまだ「蛇行で目で辿れる」。一直線の判定文に差し替える | 小（30 分） | 不要 |
| 保険として、戻りレーンを従レーンとして描き分ける案を用意する（細く・暗く・流れドット無し。View のみの変更） | 小〜中（1 日） | **前提**。(22) を見て「輪に見える」と言われた場合だけ入れる。先に入れると判定対象が変わる |
| 工程順の読みやすさ：P1 を東側へ寄せた配置を実測する（搬送量が変わるので定常・長期ランの再測定が必須） | 中（2〜3 日、測定込み） | **前提**。佐事が順序を気にした場合だけ |

## 3. グラフィック：ドット絵

**要求**：ドット絵（可愛く・読みやすく）。平面的でチープなベクタ絵は却下済み。2.5D 立体感は不採用。

**現状**

- 装置 20 機種すべてにドット絵スプライトがある。PIL の手続き描画をネイティブ解像度で作り、×4 の最近傍拡大で書き出す方式。本体合計 115,088 B【ログ：r3-implementation-log §3、gate3-dot-log §1】。
- 環境（FOUP・ストッカー・投入口／出荷口・売地看板・施設 3 棟・砂時計・切断プラグ）は画像ではなく、Canvas 上の矩形合成による「ピクセル調」の手続き描画【コード：MapScene.swift:2052-2128】。寸法はセル寸法に比例し、ピクセルグリッドには揃えていない。
- **マップ上のスプライト描画に補間指定が無い**。`drawSpriteTool` は `Image(body.image)` をそのまま矩形に描く【コード：MapScene.swift:2033】。`.interpolation(.none)` があるのは建設ドロワーのサムネイルだけ【コード：BuildDrawer.swift:485】。
- **1 ドットの表示寸法が小さい**。スプライトのネイティブ解像度は幅 144〜160 ドット（例：D1 は 576px÷4＝144 ドットで 2 セル幅、L1 は 640px÷4＝160 ドットで 4 セル幅）【コード：design/sprites/d1.json・l1.json】。セル 24pt×ズーム、@3x 端末で計算すると次のとおり。

| 機種 | ズーム 0.65（初期表示相当） | ズーム 0.97 | ズーム 2.0（最大） |
|---|---|---|---|
| D1（2 セル幅、drawScale 1.25） | 約 0.8 px／ドット | 約 1.2 px | 約 2.5 px |
| L1（4 セル幅、drawScale 1.15） | 約 1.3 px／ドット | 約 2.0 px | 約 4.1 px |

  初期ズームが約 0.65 になるのは R1 の実装判断【ログ：r1-implementation-log §6-1】。どのズームでも整数倍にはならない。
- 装置はすべて静止画。C1 の回転プラテンはドット絵化で外され、全機種の `layers` は空【ログ：gate3-dot-log §4、コード：d1.json・l1.json の layers】。動くのはランプ・FOUP・レールの流れだけ。
- side 方向は未制作。回転 90／270 でも正面絵を使う【コード：各 json の knownIssues】。S9c では L1×2 台が回転 90 で置かれる【コード：Layout.swift:672】。
- 却下済みのベクタ絵 `EquipmentPainter` はフォールバックとして残っている【コード：MapScene.swift:1830-1837】。スプライトは Codemagic のビルド時にスクリプトで生成されるため【コード：codemagic.yaml:31-32】、生成や読み込みに失敗するとベクタ絵が黙って出る経路がある。
- スタイル基準は「上面と右側面が見える箱型表現（奥行き 4〜5 ドット）」【ログ：gate3-dot-log §2】。

**乖離：中**（見え方は【未判定】）

方式は決定どおり。乖離の中身は「ドット絵として見えるか」で、次の 3 点が懸念【推測】。

1. 1 ドットが端末 1〜2 px、かつ補間ありの非整数倍なので、通常のズームでは「ドット絵」ではなく「細かい小さな絵」に見える可能性が高い。可愛さ・読みやすさを担うはずの太い輪郭（2 ドット）も初期表示では 2 px 前後になる。
2. 「上面＋側面が見える箱」が、不採用とした 2.5D 立体感に当たるかどうか。β3 以降の絵に対する佐事の評価は資料に残っていない。
3. 環境の手続き描画と装置スプライトでドット密度が揃っていない（R3-2 の判定項目そのもの）。

**改善案**

| やること | 工数感 | 実機判定が前提か |
|---|---|---|
| R3-1・R3-2 の判定時に「ドットが見えるか」「立体感は許容か」を明示的に聞く | 0 | 判定そのもの |
| マップ描画を最近傍補間にする（1 行相当。この VM では SwiftUI を型検査できないので実ビルドでの確認が要る） | 小（半日） | 不要だが、非整数倍の最近傍はドット幅が不揃いになるので下の案とセットが望ましい |
| ネイティブ解像度を粗くする（1 機種あたり幅 32〜48 ドット級に描き直し、整数倍ズームへスナップ）。生成スクリプトが決定的なので全機種を再生成できる | 中〜大（3〜5 日、20 機種の目視込み） | **前提**。「ドット絵に見えない」と判定された場合 |
| ベクタ絵フォールバックの扱いを決める（スプライト欠落時はプレースホルダを出して気づけるようにする） | 小（半日） | 不要 |
| 稼働中アニメ（2 コマ程度）を律速になりやすい機種から追加 | 中（機種あたり半日） | 前提（静止が寂しいと言われた場合） |

## 4. 操作感：ドラッグで動かして、確定はボタン

**要求**：タップ確定がシビアなのは不可。ドラッグで動かし、確定はボタン（β1 実機フィードバック）。

**現状**

- 装置の配置・移動は要求どおりの作り。ゴーストは建設タイルのタップで画面中央に出て、ドラッグで動き、確定は浮動ツールバーの「ここに置く（価格）」「ここへ移動」だけ【コード：MapScene.swift:659-661・1432-1451】。タップやドラッグの離しでは確定しない。
- 吸着：半径 2 セル以内の置けるセルへスナップ【コード：MapScene.swift:1117、ログ：fix-beta1-feedback-log】。
- 掴める範囲：ゴーストとその周囲 1 セル。それ以外のドラッグはパン【コード：MapScene.swift:721-728】。
- 長押し 0.35 秒で持ち上げ、触覚 `.medium`。遊び 6pt【コード：MapScene.swift:406-408・762】。
- ゴースト表示中に別の場所をタップすると、ゴーストがそこへ飛ぶ【コード：MapScene.swift:815-822】。
- 確定ボタン列は `controlSize(.small)` の 3 ボタン（回転／確定／キャンセル）が横並びで、ゴーストの直下 10pt に出る【コード：MapScene.swift:1407-1408・1453】。
- 初期ズーム約 0.65 では 1 セルが約 15.6pt。2×2 の装置は約 31pt 四方【コード：MapScene.swift:28、ログ：r1 §6-1】。
- 建設タイルをマップへドラッグして持ち出す操作は未実装【ログ：r1 §6-4】。
- **レールは確定ボタン方式ではない**。なぞって指を離した時点で敷設・課金される（1 セル 200 万円）【コード：MapScene.swift:699-702、Engine.swift:1221】。救済は「元に戻す」1 段と全額返金。
- **レールモードの敷設ツールで既存レールをタップすると、向きが時計回りに変わる**（無償・確認なし）【コード：MapScene.swift:877-881】。「元に戻す」が覚えるのは新規セルだけなので、この変更は取り消せない【コード：MapScene.swift:884】。本線のセルを 1 回誤タップすると流れが変わり、寸断や詰まりになりうる。
- 消しゴムはタップ即撤去【コード：MapScene.swift:873-876】。
- Dynamic Type 最大では、浮動ツールバーの高さ計算（52／80pt 固定）からボタン列がはみ出す可能性が申し送られている【ログ：dynamic-type-log 申し送り】。
