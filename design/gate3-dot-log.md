## 1. 制作方法

再現スクリプト：`design/sprites/make_dot_sprites.py`（PIL 手続き描画）。

| 工程 | 内容 |
|---|---|
| 1. 作画 | ネイティブ解像度（最終寸法の 1/4）で PIL プリミティブ（矩形・楕円・多角形）により機種ごとに作画。箱型パーツは「上面＋右側面が見える」共通ヘルパー `box3d` で統一 |
| 2. 輪郭パス | アルファマスクを 1dot 膨張させ、シルエット外周に輪郭色の縁を付与（太い輪郭の担保） |
| 3. 拡大 | ×4 NEAREST 拡大。ピクセルグリッドが揃い、補間ぼかしは一切入らない |
| 4. 配置 | `design/sprites/generated/`（マスター）と各 `.imageset` へ同一バイトを配置 |

方式選定の理由：画像生成＋ピクセル化後処理は、グリッド整列・パレット統制・機種間の画角統一が不確実で没率リスクがある。手続き描画は決定的に再生成でき、色数と輪郭を仕様として固定できるため採用した（制作方法は自由という指示の範囲内）。

- 試行回数：**全機種とも作画1回で採用**（コンタクトシート目視で、シルエット判別・スタイル統一・グリッド整列を確認。作り直しなし）
- シグナルタワーは全機種とも描いていない（状態ランプはコード描画が正、という従来前提を維持）

## 2. スタイル統一の基準

| 項目 | 基準 |
|---|---|
| グリッド | 1dot = 最終画像の 4px（×4 NEAREST）。全機種共通 |
| 輪郭 | 濃紺グレー `#222636`。パーツ輪郭 1dot ＋ シルエット外周に膨張パスでもう 1dot（表示上は太輪郭） |
| 本体パレット | クリーンルーム白 `#F2F5FA`（上面）／ `#D8DFEA`（前面）／ `#A8B4C6`（側面・帯）／ `#768296`（暗部）／ `#4A5264`（濃面）の 5 階調を全機種共通 |
| アクセント | 工程色を 1 色だけ使う。色は `LineView.swift` の `ProcessType.accent` と同色系（CMP=青、露光=橙、成膜=ティール、エッチ=紫、注入=緑、検査=インディゴ、PKG=茶）。ラベル・ランプの色と絵の色が一致する |
| その他共通色 | ガラス `#94D6EE`＋白ハイライト、FOUP ベージュ `#EEDCB3`（コード描画 FOUP と同系）、金 `#F2C95C`（チップ等） |
| 色数実測 | 12〜20 色/機種（透過含む） |
| 画角 | 正面〜やや見下ろし。上面と右側面が見える箱型表現（奥行き 4〜5dot）。下端アンカー＋上方向オーバードローという既存の描画契約はそのまま |
| かわいさの要素 | 特徴パーツの誇張（レンズ・リール・プラテンを大きく）、白いキラキラ（スパークル）1〜2 点、丸みのある楕円パーツ多用 |

## 4. C1 可動部 mov1 の判断：**外す**（アセット＋メタデータの範囲で実施済み）

- 判断：ドット絵版 mov1 は今回作らない。セミリアル版 mov1（プラテン切り抜き）はドット絵本体と質感が大きく異なり、回転時に違和感が際立つため流用もしない
- 実施内容（コード変更ゼロ）：
  - メタデータ `c1.json` の `layers` を空配列にした。描画側（FloorGridView `drawSpriteTool`）は `front.layers.first` が無ければ可動部描画をスキップする既存仕様のため、そのままフォールバックする
  - `eq_c1_front_mov1.imageset` と マスター `design/sprites/generated/eq_c1_front_mov1.png` をクローン内から削除
  - `Scripts/generate_sprites.sh` からも mov1 ブロックを除去（§5）。ビルド時に再生成されることもない
- 影響：CMP のプラテン回転アニメ（processing 中のみ、ズーム 0.5 以上）は β3 では無くなる。プラテン自体は本体に描き込まれているため工程の判別には影響しない。将来ドット絵 mov1（正円テクスチャのドット絵プラテン）を試作する場合は、gate1 の知見どおり「単体・影なし・模様のみ」で作ること

## 6. 環境（床・FOUP・ストッカー）との相性 — 申し送り（コードは変更していない）

描画側（FloorGridView.swift）の環境は第2ゲートのベクタ手続き描画のまま。ドット絵機種と並べたときの所見：

1. **FOUP**：色味は揃えた（コード描画 FOUP のベージュ (0.93, 0.86, 0.70) とドット絵側 FOUP スロットは同系）。ただし FOUP 本体はベクタの滑らかな角丸矩形で、ドット絵機種の横では質感差が残る。将来 FOUP を小さなドット絵スプライト化すると統一感が上がる（レール上・ポート内・ストッカー内は同じ描画関数のため 1 箇所で効く）
2. **床**：市松＋グレーチング孔ドットという手続き描画はもともとドット寄りで相性は良い。ただし床ドットのピッチはセル寸法依存、機種ドットは 4px グリッド固定のため、ズーム段階によって粒度の喧嘩が起きないか実機で見たい
3. **ストッカー**：ラック＋ミニ FOUP スロットはベクタ描画。機種側がドット絵になるとストッカーだけ浮く可能性がある。β3 実機で確認
4. **状態ランプ・モデル名ラベル**：コード描画（ベクタ円＋テキスト）のまま。情報表示なので併存は問題になりにくいが、ランプの滑らかな円とドット絵の対比は実機で確認
5. **接地影**：ドット絵側に楕円の接地影を描き込んだ（セミリアル版は切り抜き時の落ち影がわずかに残る程度だった）。コード側に装置影はないため二重影にはならない。床の市松との重なりで影が濃く見えすぎないか実機で確認

## 7. β3 取り込み手順

1. 本体 PNG 7 点を取り込む：`FabTycoon/Assets.xcassets/eq_<id>_front_body.imageset/eq_<id>_front_body.png` と `design/sprites/generated/eq_<id>_front_body.png`（同一バイト）。手順 4 のスクリプトを取り込む場合は Codemagic が imageset 側を生成するので、generated 側 7 点の同期だけでもよい

5. 制作資産を追加する：`design/sprites/make_dot_sprites.py`（再生成用）と `design/sprites/dot-contact-sheet.png`（参照用）。**pbxproj は無変更**（従来方式どおり）
