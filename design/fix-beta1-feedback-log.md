## ① 流れの可読性

### 1. 投入口（IN）／出荷口（OUT）の大きな明示 — `FloorGridView.swift`
- 施設の上に日本語ラベルプレート「投入口 IN」（緑）／「出荷口 OUT」（青）を描画。白フチつきのピル型で、施設へ向かう小さな三角ポインタつき（`drawPortLabel`）。
- 施設の枠に脈動するリング（1.6 秒周期、α 0.15〜0.75）を追加し、視線を集める。
- 施設はプレイヤーが移動できるため、プレートとリングは施設位置に追随する（テンプレート固定の描画ではない）。

### 2. 工程順バッジ — `FloorGridView.swift` / `Layout.swift`
- 各装置の左下に工程順バッジ（工程カラーの丸＋白抜き数字）を常時表示。番号はルート（`RouteBuilder.routeSteps`）で工程が最初に現れる順位で、現在ノード・露光クラスに応じて決まる（28nm 初期は ①成膜 ②露光 ③エッチング ④注入 ⑤検査 ⑥CMP ⑦PKG。検査は層5、CMPは層11で初出するためこの順）。
- 工程名（shortName）はセルサイズ 20px 以上（≒ズーム 0.83 以上）のときだけバッジ右に併記。引いた表示では番号だけにして邪魔にならない。
- 順位の算出は Models 側の `RouteStepOrder.ranks(node:lithoClass:)` に置き、View と HeadlessCheck で共有。

### 3. レールの進行方向アニメーション強化 — `FloorGridView.swift`
- 従来の静止シェブロンに加え、各レールセルに進行方向へ流れる光点（シアン、0.9 秒周期でセル 1 個分を移動）を追加。
- 全セル分を 1 つの Path にまとめて 1 回の fill で描くため、セル数が増えても描画コールは増えない（fps への影響を抑えた方式）。
- 流れる向きはレールセルの出口方向そのものなので、FOUP の移動と合わせて「どちらへ流れるか」が読める。

### 4. テンプレートの並び替え — `Layout.swift`（`LayoutTemplate.starter16`）
- 監査結果：上段（西→東）は 成膜 → 露光 で正しかったが、下段（東→西）は エッチング → **CMP → 注入** → 検査 → PKG で、ルートの初出順（…→ 注入 → 検査 → CMP →…）と 2 箇所で逆転していた。これが「辿っても工程順にならない」一因。
- 並べ替え：I1（4×2）を下段 (6,10)、Q1（2×2）を (4,10)、C1（2×2）を (2,10) へ。下段は E1 群（x10〜15）→ I1（x6〜9）→ Q1（x4〜5）→ C1（x2〜3）→ P1（x0〜1）と連続し、上段から通して 成膜 → 露光 → エッチング → 注入 → 検査 → CMP → PKG と目で辿れる。P7 チェックで順位列 [1,1,2,2,3,3,3,4,5,6,7] の単調性を確認済み。
- レール配置・本数（40 セル）は不変。したがって CONWIP 運転点 45、`paidRailPoints`（無償レールの返金 0）の判定、旧セーブ互換には影響しない。リング機構そのものはシミュレーションの裏側に残置。
- テンプレートは新規ゲームの初期配置にのみ効く。既存セーブの配置は変わらない（装置の位置はセーブ側が正）。
- 副次効果：P6 の初回ロット完了が 314 tick → 244 tick に短縮（搬送距離が縮んだため。条件は 720 tick 以内で余裕あり）。

## ② 配置モードの操作性 — `FloorGridView.swift` / `Layout.swift`

- **ドラッグ移動**：配置中（パレット選択／移動中）はフロアのドラッグがパンではなくゴースト移動になる。ドラッグでは確定しない。
- **近傍スナップ**：ゴーストは `FloorLayout.snappedOrigin`（Models 側、半径 2 セル）で「置けるセル」へ吸着する。範囲内に置けるセルが無ければ指の位置のまま赤ゴースト表示（置けない理由は下部バーに出る）。
- **確定ボタン分離**：再タップ確定を廃止。タップ／ドラッグはゴースト移動のみ。下部バーに「ここに置く」（移動時は「ここへ移動」）ボタンを新設し、置ける状態のときだけ有効化。「キャンセル」も明示（従来の「やめる」を改名）。
- **移動開始の改善**：「移動」を押すとゴーストが現在位置から出るので、そのままドラッグで動かせる。
- 回転ボタンは従来どおり（ゴーストの回転にもスナップが追随する）。

## 実機で確認してほしい操作手順

### ①の確認
1. 新規ゲーム（またはテンプレートが効く状態）でフロアを開く。投入口に「投入口 IN」の緑プレート＋脈動枠、出荷口に「出荷口 OUT」の青プレート＋脈動枠が出ているか。
2. 装置の左下に ①〜⑦ のバッジが出ているか。上段を左から、右端を下りて下段を右から左へ目で辿り、番号が ①成膜 → ②露光 → ③エッチング → ④注入 → ⑤検査 → ⑥CMP → ⑦PKG の順に増えるか。
3. レール上の光点がレールの向きに流れているか。FOUP の進む向きと一致しているか。fps が落ちていないか（特にズームアウト全景と 48×48 拡張時）。
4. ピンチで引くと工程名が消えて番号だけになり、寄せると工程名が戻るか。

### ②の確認
1. 編集 → 装置で、倉庫のパレットから装置を選ぶ。フロアをドラッグするとゴーストが指に追随し、置けるセルの近くで吸着するか。置けない場所では赤くなるか。
2. 「ここに置く」を押したときだけ配置され、タップやドラッグの離しでは確定しないこと。
3. 配置済み装置を選んで「移動」→ ゴーストが現在位置から出て、ドラッグで動かせること。「ここへ移動」で確定、「キャンセル」で元に戻ること。
4. 回転ボタンを押したとき、回転後の形でスナップし直されるか。

## 申し送り

- テンプレート入替は新規ゲームのみに効く。既存セーブ（β1/β2 で始めたデータ）は旧並びのままなので、実機確認で新規並びを見たい場合は新規ゲームで確認すること。
- 流れドットと脈動枠は TimelineView のアニメーションに乗る。既存の pause 条件（レール上ロットなし＆ボトルネックなしで停止）では静止する。常時アニメーションが要るなら pause 条件の見直しが別途必要。
- 工程名ラベルの表示閾値（セル 20px）は実機の見え方で調整可。バッジ番号はスプライト機種でもベクタ機種でも同じ位置（左下）に出る。
- 本クローンは未統合・未 push。取り込み時は Track A/B と同じく FloorGridView.swift の競合に注意（本変更は β2 統合済み本線が起点なので、起点が同じなら競合しない）。
